# 插件加载与 SDK 优化

[返回 Backlog](./README.md)

状态：planned。优先级：P1。依赖：[宿主接口](./services-and-host-api.md)、[插件会话](./plugin-windows-and-sessions.md)。目标是减少启动与搜索时加载的代码，并缩短插件本地开发反馈周期。

## 现状问题

启用插件的入口在主页面动态 import，matcher 与搜索共享执行环境。`frontend/src/lib/plugin-execution.ts` 为兼容全局 `window.watools` 串行执行；UI 插件直接注入宿主 runtime。本地改动缺少完整开发加载和诊断流程。

2026-10-06 的 [剪贴板优化](../architecture/implementation-mechanism.md#剪贴板原文与呼出性能)已增加 `matchPreview` 有界元数据上下文，六个官方插件匹配与完整执行上下文分开；旧入口保留有界兼容路径，并优化启动快照交付。它没有实施本目标中的完整 manifest SDK、按需代码加载或 Worker；本目标仍为 planned。

同日后续整理把启动器状态收敛为内联／快照 `LauncherInput`，加载边界统一规范化 matcher，旧适配集中维护，真实执行仅通过一个原文解析边界。它属于现有调用链与类型重构，不标记本 backlog 的其他目标完成。

## 实施范围

- 优先从 manifest 读取声明式搜索规则，执行或打开时加载代码；旧函数 matcher 通过明确兼容路径维护。
- 新 SDK 显式传入上下文与受限能力，声明版本和支持范围，提供类型、模板与兼容测试。
- 增加开发目录加载、指定插件重载、错误展示和示例数据；正式发布仍用可验证的 `.wt` 包。
- 重载不破坏 revision 资源一致性，明确运行实例保留旧版或重建的行为。
- 适合的耗时任务进可终止 Worker，定义超时、取消和异常恢复；DOM 依赖旧插件另行兼容。
- 对启动、搜索、加载耗时与资源先测基线，再优化缓存和 revision 回收，不预设改善倍数。

## 验收与验证

- 未执行插件不必在启动时加载全部业务代码，异常 matcher 不会无界阻塞搜索。
- 修改本地插件后可重载并定位错误，无需每次打包安装；与正式包的差异有文档。
- 新插件不依赖临时替换全局 API，多实例身份和上下文不混用。
- 六个官方插件保持可用，旧 SDK 兼容与弃用策略明确。
- 超时、取消、退出和重载释放请求及执行资源。

Worker 不构成不可信代码沙箱，权限另见 [信任与权限目标](./plugin-trust-and-permissions.md)。
