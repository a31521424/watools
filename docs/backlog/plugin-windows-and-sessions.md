# 插件会话与独立小窗

[返回 Backlog](./README.md)

状态：planned。优先级：P0。依赖：[v3 窗口与绑定](./wails-v3-migration.md)、[宿主接口](./services-and-host-api.md)。目标是插件独立于启动器运行，多实例的上下文、状态与生命周期明确。

## 现状问题

UI 插件由 `frontend/src/components/watools/wa-plugin.tsx` 在主窗口 iframe 内加载并注入 API。启动上下文在 `frontend/src/lib/plugin-context.ts` 的内存 Map 中，新窗口无法直接读取。页面缓存状态与使用次数，开放多窗口前需解决写回覆盖。

## 实施范围

- 宿主管理 PluginSession，关联插件、入口、revision、上下文与窗口 ID。新窗口用会话 ID 获取受控数据，不把完整剪贴板放入 URL。
- 区分 launcher、plugin、settings，按明确 ID 操作；隐藏启动器不隐藏或关闭插件窗口。
- 明确重复打开的实例策略、会话有效期、上下文领取规则、关闭后的取消与清理。
- 后端作为状态权威，按实例或订阅范围分发事件；使用次数由原子增量或幂等事件更新。
- 定义升级、禁用、卸载后的运行实例行为，revision 按实例引用回收，不删除仍被运行页面使用的资源。
- 各窗口自行初始化 SDK，宿主校验会话和真实来源。“展开”先通过上下文和可序列化状态重建，不承诺搬运实时 DOM。

## 验收与验证

- 翻译或 JSON 等真实插件从搜索结果打开独立窗口，隐藏启动器后继续工作。
- 至少两个实例的输入、HTTP 取消、存储、事件和计数不串用或覆盖。
- 关闭重开、升级、禁用和卸载行为一致，没有残留请求、订阅或无界 revision 积累。
- macOS 与 Windows 分别验收焦点、中文输入法、Esc、置顶、多屏、DPI 与关闭行为；未验证项单独列出。
- 不能只凭会话 ID 或前端提供的 packageId 认定调用有权访问其他插件数据。
