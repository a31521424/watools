# 插件信任与权限边界

[返回 Backlog](./README.md)

状态：planned。优先级：P1。信任模型可先梳理；执行依赖 [宿主接口](./services-and-host-api.md)、[会话](./plugin-windows-and-sessions.md) 与 [SDK](./plugin-loading-and-sdk.md)。目标是明确可访问能力与资源，不把执行环境分离误当作授权。

## 现状问题

原始审查 R19 尚未闭环。UI 插件可以接触注入的宿主 runtime，前端 packageId 不能作为可信身份。本地凭据文件权限也不建立插件间隔离。

## 实施范围

本阶段服务于开发者自用和可信插件：先明确身份、会话、数据归属及敏感信息处理规则。面向任意不可信第三方插件的完整沙箱与权限交互延期，恢复条件是用户明确提出开放第三方插件需求；该延期不意味着 R19 已解决。

### 当前自用范围

- 明确只安装开发者自己维护或主动信任的插件，记录宿主实际暴露能力与未隔离边界。
- 可信插件的实例、上下文和存储作用域关联正确，不因并发、重载或关闭误写其他插件数据。
- 凭据和完整剪贴板不进入默认日志，开发测试不使用真实密钥。
- 为后续来源校验与受限 SDK 留下明确接口，避免把前端 packageId 当成安全证明。

### 延期的第三方隔离范围

- 明确继续可信模型还是支持受限第三方插件；隔离验证前不宣称可安全运行任意代码。
- 定义 HTTP、文件、剪贴板、存储、凭据和窗口的授权范围、默认行为、撤销与审计。
- 身份由宿主验证的实例与真实通信来源关联，不由自行声明 packageId 或可伪造会话字段决定。
- 隔离资源、导航、通信和生成绑定，防止绕过 SDK 调用其他宿主方法。
- 验证 WebView 与 Worker 隔离限制，记录跨 origin、帧和桥接行为；额外执行环境另行设计。
- 保持 macOS 不接 Keychain，说明本地明文和 Windows DPAPI 差异。

## 验收与验证

本阶段先验证可信插件正常调用、会话不串用、数据不误写、敏感信息处理与限制说明。记录对应结果后可完成当前自用范围，但必须继续保留第三方隔离延期记录，不能关闭 R19。

以下越权拒绝与绕过检查属于恢复第三方隔离任务后的验收，不作为当前自用阶段的完成条件。

- 正常插件可完成获准操作；伪造身份不能访问其他插件存储和凭据。
- 未授权操作、跨插件资源、失效会话和禁用后调用被宿主拒绝。
- 不能通过直接绑定、全局 runtime 或其他通信绕过 SDK。
- 若无法建立可靠隔离，明确保留可信模型及残留风险，不将 R19 标记解决。
